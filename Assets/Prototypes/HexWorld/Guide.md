# 육각 영역 프로토타입

`Assets/Prototypes/HexWorld/Scenes/HexWorld.unity`를 열고 Play합니다. 기존 버전은 `Assets/Prototypes/LegacyUGUI/Scenes/SampleScene.unity`에서 그대로 비교할 수 있습니다.

## 테스트 순서

1. 시작 가게 한 칸이 소유 상태이며, 진열 선반 타일 두 개가 보관함에 있습니다. 주변 바닥은 보이는 칸일 뿐 소유 영역이 아닙니다.
2. **타일 배치 · 일시정지**를 누릅니다. 설치 가능한 인접 칸은 녹색, 불가능한 위치의 미리보기는 빨간색입니다. 마우스로 위치를 확인하고 왼쪽 클릭하여 확정합니다.
3. **이동**은 부품 타일을 먼저 선택하고 목적지를 클릭합니다. 확정 전에는 원래 타일이 남습니다. **회수**는 부품 타일을 클릭해 보관함으로 되돌립니다. 시작 타일은 고정이며, 남은 영역이 시작 타일과 분리되는 이동·회수는 거절합니다.
4. **배치 종료**로 재개합니다. 배치 모드에서는 손님 이동·대기 시간·접대 시간이 모두 멈추며 카메라 조작은 계속 가능합니다.
5. 현재 보유 골드 3 / 8 / 15 / 24…에 도달하면 아이템 세 개 중 하나를 선택합니다. 선택 시 골드는 소비하지 않습니다. 가게 부품을 선택하면 보관 타일 한 개를 얻습니다. **테스트: 골드 +1** 버튼으로 빠르게 확인할 수 있습니다.

## 상점과 재화

- **상점 열기**를 누르면 게임이 일시정지됩니다. 상품은 진열 선반 타일 3골드, 빠른 접대 영구 강화 5골드, 접대 가속 물약 2골드입니다.
- 부품은 보관 타일로 들어갑니다. 영구 강화는 기존 아이템과 동일한 보유 레벨에 중첩되고 즉시 접대 성능에 반영됩니다. 최대 레벨에 도달했거나 잔액이 부족하면 구매할 수 없습니다.
- 물약은 소모품 수량으로 보관합니다. 상점의 **1개 사용** 또는 화면의 **가속 물약 사용**으로 1개를 소비해 20초 동안 접대 속도 보너스 +100%를 적용합니다. 효과 중에는 중복 사용할 수 없습니다.
- 물약 시간은 게임 진행 시간 기준입니다. 상점·배치·레벨업 선택 중에는 멈추고, 만료되면 영구 강화만 남습니다.
- 보유 골드는 구매 시 감소합니다. **레벨업은 현재 보유 골드로 판정합니다.** 예: 누적 8골드여도 보유 5골드라면 3레벨의 8골드 조건을 충족하지 않습니다. 상점이나 선택창을 닫은 뒤 남은 골드로 다음 조건을 다시 확인합니다. 이미 얻은 레벨은 지출로 내려가지 않으며 레벨업 자체는 골드를 소비하지 않습니다.
- 상품은 `Data/ShelfOffer.asset`, `ServiceOffer.asset`, `PotionOffer.asset`에서 키·문구 키·사진·가격·종류·보상·지속 시간을 편집합니다. 새 상품 UI는 UGUI 카드에 데이터와 버튼 참조를 연결합니다.
- 상점 UI는 씬과 `Prefabs/ShopUI.prefab`에 저장되어 있습니다. 후자를 단독 배치할 때는 HexShopSystem의 Game 참조를 해당 씬 컨트롤러에 연결합니다.

## 카메라와 캐릭터

- 3D 육각 프리즘 위에 캐릭터와 가게·부품 건물 모두 2D 스프라이트로 배치했습니다. 캐릭터는 임시 두 프레임 걷기 모션을 사용합니다.
- 초기 카메라는 가게 정면(좌우 회전 0°)에서 30°로 내려다봅니다. 오른쪽 마우스 드래그 또는 슬라이더로 수평 정면인 0°부터 65°까지 조절합니다. 좌우 회전은 고정입니다.
- 휠 또는 슬라이더로 기본 거리의 0.6–1.8배까지 조절합니다. **시점 초기화**로 기본값을 복원합니다.
- 캐릭터와 건물은 하단 피벗으로 바닥 기준 위치를 유지하고, 그림 면 전체를 카메라에 맞춰 정렬합니다. 각도가 높아져도 그림이 얇아지거나 세로로 눌리지 않습니다. 지면 그림자와 바닥 기준 깊이 정렬을 함께 사용하며 손님 게이지는 그림 위에 유지합니다.
- `Art/ShopFront.png`, `ShelfFront.png`는 교체 가능한 정면 임시 아트입니다. 새 이미지를 사용할 때 하단 피벗과 크기를 맞춥니다. `HexCameraFacingSprite`가 에디터와 Play 양쪽에서 시점을 정렬합니다.
- 손님은 좌우에서 등장합니다. 반응하지 않는 손님은 검정색/불투명도 40%로 반대편으로 통과하며 가게 주변에서 대기하지 않습니다. 반응 가능한 손님은 색상이 있으며 바로 대기 위치로 향하거나 가게 주변 배회 후 확률적으로 대기에 합류합니다. 가게 주변의 대기 위치에 도착했을 때부터 10초 대기 게이지가 표시·소모됩니다.
- 등장 간격은 0.77초에서 1.155초, 최대 손님 수는 48명에서 32명으로 줄여 약 2/3 수준입니다. HexPrototype의 Visitor Chance(반응 가능성), Direct Queue Chance(즉시 대기 위치로 향할 확률, 기본 50%), Browsing Queue Chance(배회 중 대기 합류 결정 확률, 기본 35%), Browse Decision Seconds(배회 지점 도착 후 판단 간격, 기본 3초)를 조정할 수 있습니다. 판단에 실패하면 다른 주변 지점으로 배회를 계속합니다.
- 타일 바닥 면은 표시하지 않고 육각 윤곽선만 그립니다. 소유·설치 가능·선택·불가 상태는 선 색으로 구분하며, 숨겨진 타일 Collider로 설치 위치를 선택합니다. 수평 시점에서는 바닥 선들이 좁게 보이므로 배치할 때 카메라를 높일 수 있습니다.

## 자산과 확장

- `LegacyUGUI`: 기존 씬·UI·아이템·전용 스크립트. GUID를 유지해 이동했으며 기존 플레이 동작을 보존합니다.
- `Shared`: 공용 문자열 테이블/조회, 아이템 정의, 골드 곡선, 맑은 고딕 연결. 새 버전에서도 사용하므로 기존 버전을 삭제할 때 남겨야 합니다.
- `HexWorld`: 새 씬·프리팹·스프라이트·재질·아이템 데이터·문자열·입력·전용 스크립트. 새 씬은 LegacyUGUI 자산에 의존하지 않습니다.
- UI는 씬 및 `Prefabs/HexWorldUI.prefab`에 저장된 UGUI입니다. 런타임에서는 상태와 값만 변경합니다. 실제 씬의 UI 참조를 직접 편집할 수 있습니다.
- `Data/DisplayShelfTile.asset`은 타일 키·문구 키·아이콘·색상입니다. 새 종류를 추가하면 Board의 Tile Types와 Game의 Tile Rewards에 연결합니다.
- 아이템 후보는 `Data/HexCatalog.asset`, 강화 효과는 각 아이템의 Effects, 레벨 조건은 `Data/GoldCurve.asset`, 영어/한글 문구는 `Data/HexWorldStrings.asset`에서 조정합니다.
- `Data/HexWorld.inputactions`의 의미 기반 World 액션으로 조작합니다. `HexWorldInput.Rebind(actionName, bindingIndex, path)`로 변경·저장할 수 있습니다. 설정 화면은 아직 없습니다.
- 시작 시 61칸의 중립 바닥을 보여주며, 소유 영역이 가장자리에 닿으면 다음 인접 칸을 자동 추가합니다. 중립 칸은 연결 검사에 포함하지 않습니다.
- `Stack Store > Hex World > Validate Tile Rules`에서 배치·연결·수량 보존 검사를 실행할 수 있습니다. 에디터 씬 생성 메뉴는 이미 만들어진 씬을 덮어쓰지 않습니다.

## 현재 범위

플레이 상태는 Play 종료 시 초기화됩니다. 저장·불러오기, 실제 아트, 캐릭터 방향별 애니메이션, 시설 가구 자체를 피하는 세밀한 경로 탐색, 시작 전 배치 저장은 이후 확장 범위입니다. 현재는 고정 가판대 주변 접대 흐름과 플레이 중 배치·재배치를 테스트합니다.

폰트는 Windows 맑은 고딕을 직접 불러옵니다. **알파 개발 시 프로젝트에 포함·배포 가능한 정식 폰트를 추가해야 합니다.**

배치 미리보기 칸과 화면상으로 겹치는 캐릭터·건물·지면 그림자는 원래 투명도의 35%로 표시됩니다. 위치를 옮기거나 배치를 종료하면 원래 색상과 투명도로 돌아갑니다. 타일 윤곽은 월드 리소스보다 아래에 그려집니다.

손님 유형 표시 비교: [검정 반투명 통행인과 색상 방문 손님](Documentation/Screenshots/14-Reactive-And-Passing-Guests.png).

손님은 가게를 중심으로 반경 2.3의 원형 위치에 분산해 대기하며, 자리가 차면 바깥쪽 원의 빈 위치를 사용합니다. 대기 자리는 예약되어 겹치지 않고, 접대나 이탈 시 반환됩니다. 음식은 현재 대기 중인 손님 중 가장 먼저 대기 위치에 도착한 손님에게 던집니다.

음식은 저장된 FlyingFood 프리팹의 2D 스프라이트이며 0.65초 동안 높이 1.6의 포물선으로 이동합니다. 대기 게이지는 접촉 즉시 표시·감소하며, 비행 중 수령 손님은 게이지를 표시한 채 인내 시간을 소모하지 않고 위치를 유지합니다. 도착 시 골드 +1과 퇴장을 처리합니다. 배치·상점·레벨업 선택 중 비행도 일시정지됩니다. Waiting Radius 및 FlyingFood의 Flight Seconds/Arc Height로 조정할 수 있습니다.

주변 대기·음식 투척 화면: [가게를 둘러싼 손님과 포물선 음식](Documentation/Screenshots/15-Surrounding-Guests-Food-Arc.png).

배부 순서는 접촉 순서에 따른 선입선출입니다. 새 손님이 접촉해도 앞서 대기한 손님이나 비행 중인 음식의 대상은 바뀌지 않습니다.

레벨업 후보에 능력 아이템 두 종류가 추가되었습니다. **푸짐한 한 상**은 레벨당 투척 음식 +1개, 최대 3레벨로 총 4개까지 늘립니다. 한 번의 접대 주기에 서로 다른 손님에게 접촉 순서대로 배부하며 손님이 부족하면 해당 수까지만 던집니다. **거리의 초대**는 레벨당 반응 가능한 방문 손님 등장 확률 +10%p이며 확률 상한은 100%입니다. 기존 손님의 반응 분류는 유지합니다.

## 시설·벽·층 확장 (2026-10-06)

- 시설 선택 목록은 기존 진열 선반과 테이블·주방·창고·계단·숙박·출입구입니다. 테스트를 위해 시작 보관함에 각 종류를 2개씩 제공합니다. 한 칸 이상 떨어진 설치는 불가능하며, 설치된 시설만 소유 영역입니다.
- 테이블 좌석은 설치할 때 2~4개로 무작위 결정됩니다. 이동하면 좌석 수를 유지하고, 회수 후 다시 설치하면 새로 결정됩니다. 손님은 빈 좌석을 예약한 뒤 벽을 피해 이동하여 착석합니다. 테이블 대기는 기본 20초, 접대 보상은 2골드입니다. 바깥 대기는 기존 10초·1골드입니다. 두 종류 모두 도착 시 게이지가 시작되고 접촉 순서대로 음식이 나갑니다.
- 주방에는 노란색 UGUI 안내로 **배치된 직원이 없습니다**를 표시합니다. 아르바이트 기능이 추가되면 직원 배치와 요리 생성에 연결할 예정입니다. 현재 직원이나 자동 요리 생성은 없습니다.
- 창고는 별도 종류와 배치 데이터만 준비했습니다. 재료 보관·관리 기능은 이후에 연결합니다.
- 숙박은 한 타일에 한 명이 이용합니다. 기본 30초 후 6골드를 지급하고 퇴장하며 음식 대기열에는 들어가지 않습니다. 이용 시간은 배치·상점·레벨업 선택 중 멈춥니다.
- 이용 중이거나 손님이 자리를 예약한 테이블·숙박 시설은 이동·회수할 수 없습니다. 퇴장·시간 초과·손님 제거 시 자리를 반환합니다.

### 벽과 출입 경로

- 소유 타일끼리 맞닿은 면에는 기본 벽이 없고, 비소유 영역과 맞닿은 면에는 벽이 생깁니다. 시작 가판대와 출입구 타일의 외곽은 기본적으로 열려 있습니다.
- **벽 편집** → 소유 타일 클릭 → 왼쪽의 방향별 **짓기/허물기** 버튼을 사용합니다. 방향은 초기 가게 정면 시점을 기준으로 오른쪽, 앞 오른쪽, 앞 왼쪽, 왼쪽, 뒤 왼쪽, 뒤 오른쪽입니다. 편집 중 게임은 일시정지됩니다.
- 손님 경로는 육각 셀과 열린 면을 따라 탐색합니다. 벽으로 막힌 면은 통과하지 않고 다른 열린 방향으로 우회합니다. 벽을 바꾸면 이동 경로를 다시 계산합니다.
- 모든 소유 타일에서 실제 외부까지 도달할 수 있어야 합니다. 밀폐된 중정으로 열린 면만으로는 통로가 있다고 인정하지 않습니다. 마지막 외부 통로나 시설로 가는 유일한 통로를 닫는 벽 조작은 거부합니다.
- 시설 설치·이동·회수로 외곽 벽이 바뀌어 통로가 없어지는 경우, 필요한 지상 벽 한 면을 자동으로 열어 외부 경로를 유지합니다. 출입구가 있어도 그 바깥이 다른 벽으로 완전히 막히면 유효한 통로로 인정하지 않습니다.

### 층과 계단

- 계단 타일을 설치하면 다음 층과 연결합니다. 새로 생긴 층은 계단의 연결 타일 한 칸만 소유 상태이고, 추가 확장은 공용 보관함의 타일을 소비합니다. 다음 층 위에 계단을 추가해야 그 다음 층이 생깁니다.
- **아래층/위층** 버튼 또는 층 선택 목록으로 화면을 전환합니다. 카메라는 해당 층의 연결 타일을 중심으로 표시하고, 손님과 시설은 선택한 층만 보여줍니다. 다른 층의 손님 시뮬레이션은 계속 진행됩니다.
- 층 사이 이동은 계단 연결을 통해서만 가능합니다. 한 층에 여러 계단을 놓으면 이미 생성된 다음 층의 같은 연결 타일로 합류합니다. 새 계단마다 무료 타일을 추가하지 않습니다.
- 연결된 계단은 직접 이동할 수 없습니다. 위층이 연결 타일 한 칸만 남았고 더 높은 층이 없을 때 마지막 아래층 계단을 회수하면 빈 위층도 없어집니다. 확장된 위층의 마지막 연결 계단은 회수할 수 없습니다.
- 위층 접대도 기존 FIFO를 사용합니다. 현재 음식은 해당 층 계단 연결 지점에서 손님에게 던지는 프로토타입 연출이며, 직원 조리·층별 운반 애니메이션은 이후 연결합니다.

시설 값은 `Data/*Tile.asset`의 Kind, Minimum/Maximum Seats, Waiting Seconds, Service Gold, Lodging Seconds/Gold로 편집합니다. UI는 `Prefabs/ShopBuildingUI.prefab`, 벽·시설 안내는 `Prefabs/HexTile.prefab`, 타일 종류와 시작 보관 수량은 씬의 HexTileBoard에서 편집합니다. 문구는 영어·한글 문자열 테이블을 사용합니다.

검증 메뉴: **Stack Store > Hex World > Validate Walls Facilities And Floors**. 외부 연결, 마지막 통로 차단, 밀폐된 둘레, 벽 우회, 좌석 예약·용량·이동 보존, 계단 전용 경로, 한 칸짜리 새 층, 재고 소비 및 기존 연결·수량 보존 2,000회 검사를 실행합니다.
