# 프로젝트 작업 규칙

## 게임 UI

- 구현되는 게임 UI는 기본적으로 UGUI로 구성한다.
- Canvas, UI 레이아웃, 게이지, 텍스트 등의 구성은 Unity 에디터에서 실행 전에도 확인하고 편집할 수 있도록 씬 또는 프리팹에 저장한다. UI 전체를 런타임 코드로 생성하는 방식을 기본으로 사용하지 않는다.
- 코드는 씬·프리팹의 UI 참조를 연결하고 상태, 수치, 표시, 상호작용을 제어하는 데 사용한다. 손님처럼 동적으로 추가되는 요소는 미리 구성한 프리팹을 인스턴스화할 수 있다.
- UI를 코드로 구성하는 것이 더 적합한 경우에는 구현 전에 이유와 대안을 사용자에게 건의하고, 사용자의 판단에 따라 구현한다.

## 작업 완료 및 GitHub 반영

- 작업이 완료되면 해당 작업의 변경사항을 자동으로 커밋하고 연결된 GitHub 원격 저장소에 Push한다.
- 커밋 제목과 본문은 직접 작성한다. 제목에는 핵심 변경을, 본문에는 수행한 작업 내역의 요약과 관련 검증 결과를 설명한다.
- 커밋 제목 앞에는 커밋 당일의 Asia/Seoul 기준 날짜를 [YYYY-MM-DD] 형식으로 붙인다. 예: [2026-10-04] 규칙 갱신.
- 변경사항이 없는 확인·질의 응답에는 빈 커밋을 만들지 않는다.
- 사용자 또는 다른 작업의 무관한 변경사항은 임의로 커밋하지 않는다. 강제 Push는 하지 않으며, 인증·권한·충돌 등으로 반영할 수 없으면 그 이유와 미반영 상태를 알린다.

## 규칙 및 작업 기록

- 기록은 Assets/History 폴더의 텍스트 메모장(.txt)으로 관리한다.
- 규칙이 추가, 수정, 삭제될 때마다 Assets/History/Role.txt의 기존 규칙 내용을 갱신하여 현재 전체 규칙을 기록한다. AGENTS.md도 동일한 규칙으로 유지한다.
- 당일 작업 내용은 요약하여 Assets/History/YYYY-MM-DD.txt에 기록한다. 날짜는 사용자 시간대인 Asia/Seoul을 기준으로 한다.
- 날짜별 기록에는 지시받은 작업과 실제 수행한 작업을 구분하고, 검증 결과 및 미완료·보류 사항을 기록한다. 같은 날의 추가 작업은 기존 기록에 이어서 작성한다.
