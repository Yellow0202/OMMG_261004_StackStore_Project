1. 구조와 실행 흐름
================================================================
현행 씬: Assets/Prototypes/HexWorld/Scenes/HexWorld.unity
현행 코드/데이터/프리팹: Assets/Prototypes/HexWorld의 Scripts/Data/Prefabs
규칙·작업 기록·설명: Assets/History

ScriptableObject는 설정·후보 등 원본 데이터이다.
MonoBehaviour는 씬·프리팹의 컴포넌트로 진행과 표시를 제어한다.
일반 C# 모델은 배치·경로·음식 준비도·고용별 경험치 등 실행 상태를 관리한다.
UGUI는 씬/프리팹에 저장된 Canvas/Text/Image/Button을 참조한다.
Editor의 Authoring 코드는 에디터에서 UI/씬/프리팹을 제작해 저장하는 도구이며,
매번 인게임 UI 전체를 런타임에 만드는 방식과 구별된다.

초기화의 핵심 실행 순서(DefaultExecutionOrder)
HexSettingsBinding -500: 시작 조건·공용 설정 연결.
HexTileBoard -200: 타일 모델 초기화.
HexOrbitCamera -50: 카메라 갱신 순서 제어.
HexActorIdentity 150: 캐릭터 표시 이후 역할 이름표 갱신.

HexPrototype.Update → 소유 골드로 레벨업 확인 → 진행 가능 시 손님 생성
→ TickGuests → staffSystem.Tick → service.Tick.
배치/보상 선택/상점 중에는 게임 시간을 정지한다.
별도 LateUpdate에서 카메라·2D 방향·게이지·역할 표시를 정리한다.

접객 흐름
생성 → 통행 또는 배회/접근 → 자리 예약 → 도착 시 인내 게이지 시작
→ 접촉 순번 부여 → 도달 가능한 가장 오래된 대기 손님 선택
→ 플레이어 직접 이동 → 음식 전달·골드 지급 → 식사 후/즉시 퇴장.
숙박은 음식 배달과 별개로 체류 종료 시 숙박 골드를 지급한다.

3D 바닥은 X/Z, 높이는 Y이다. 타일 Vector2Int는 육각 axial 좌표(q,r).
내부 floor=0은 표시 1층이다.

공통 Unity 함수
Awake: 초기 참조·모델·UI 이벤트 준비. Start: 첫 프레임 전 준비.
OnEnable/OnDisable: 이벤트 구독·해제 및 등록/정리.
Update: 프레임별 처리. LateUpdate: 이동 이후 위치·방향·표시 정리.
OnDestroy: 파괴 시 예약/정적 인스턴스 정리.
OnValidate: 에디터 설정 유효 범위 보정 또는 캐시 초기화.

10. 수정 위치와 현재 구현 범위
================================================================
손님 수/속도/관심/배회: PrototypeTestSettings → Guests.
조리/플레이어 이동/일반 접객 보상: Service.
초기 골드/레벨/재고: Start (다음 Play).
카메라 각도/줌/팬 제한·복귀: Camera.
그림 기울기/벽/손님 게이지: Visual.
플레이어·직원 이름표/도형: Identity.
급여 주기/성장/업무 효율: Staff.
개별 직원 비용/초기 등급/단점: Staff.candidates의 원본.
스킬: Staff.skills의 원본.
타일 정원/시설 대기/접객·숙박 보상: tileTypes의 HexTileDefinition 원본.
보상 아이템/강화 상한·효과: itemCatalog의 ItemDefinition 원본.
레벨 목표: levelCurve의 GoldLevelCurve 원본.
판매 가격·지급·물약: shopOffers의 HexShopOffer 원본.
영어·한글: HexWorldStrings.asset.
기능 입력 바인딩: HexWorld.inputactions 및 HexWorldInput.Rebind().
UGUI 실제 계층·배치: HexWorld 씬과 관련 프리팹.

원본/실행 상태 및 범위
- 직원 경험치·미지급분은 HexEmployeeState에 있으며 후보 에셋은 변경하지 않는다.
- 골드·보유 아이템·타일 재고·손님은 실행 상태. 저장/불러오기 시스템은 없다.
- 모든 내부 숫자가 공용 설정에 있는 것은 아니다. 일부 좌표 반지름·UI 배치·
  투명화 배율 및 이전 투척 값 등은 기존 코드/프리팹에 남아 있다.
- 테이블 정원은 배치 시 정해져 이동 후에도 보존, 사용 중 회수는 제한된다.
- 직원은 현재 공용 음식 슬롯을 조리하고 배달은 플레이어가 담당한다.
  직원별 독립 음식 창고·직원 배달 명령은 현재 범위에 없다.
- 창고 재료 관리·쾌적함·자연 발생 쓰레기·실제 진상 행동은 이후 확장 대상.
- 입력 재설정 API·저장 구조는 있으나 사용자 설정 화면은 별도 작업이다.
- 알파 버전에는 배포 가능한 정식 폰트를 추가해야 한다.
- 이 설명서는 작성 시점 기준이며 이후 기능 변경 시 함께 갱신해야 한다.

HexPlayerIdleAuthoring.cs: Build는 Idle 폴더의 8방향 원본을 단일 Sprite로 임포트하고 PlayerAnimationSet.idle에 연결한다. Body는 투명 알파 경계로 신체 영역을 측정한다. 기존 정면 이동 Sprite의 보이는 높이에서 PPU를 계산하며 발 하단을 피벗으로 등록. Idle_방향.anim은 한 이미지가 반복되는 대기 클립. Validate는 참조 방향, 표시 높이 및 발 위치 일치 확인.
HexPlayerAnimationAuthoring.Build: 이동 리소스 재생성 후 Idle 폴더가 있으면 전용 Idle 재연결. HexPlayerAnimation의 기존 정지 분기가 전용 idle[direction]을 표시하므로 런타임 방향 계산은 동일.

HexPlayerWalkSheetAuthoring.cs: Build가 WalkSources의 8방향 시트를 Slice하고 기존 이동 클립/Idle 연결을 재빌드한다. Slice는 알파로 연결된 인물 8개를 찾고 4열 2행 순서로 정렬하여 동일한 정사각 프레임에 발 하단과 머리 중심을 맞춰 저장한다. 포즈를 합성하지 않으며 원본 프레임 순서대로 분리한다. Validate는 64개 프레임의 경로/순서/크기/발 피벗/Point 임포트를 확인한다. 기존 Walk 파일의 meta/GUID는 유지한다.
